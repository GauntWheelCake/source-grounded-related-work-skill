# 引用与来源核验

仅在查文献、核验引用或处理来源缺失时使用。本 skill 不绑定任何厂商工具、MCP、CLI 或其他 skill。
使用当前环境实际提供的本地读取、PDF解析、联网检索和浏览能力。

## 从稿件与本地材料开始

- 用户给出目录时，查找实际主稿和参考文献文件；不要根据对话中的简称猜文件名。
- 读取相关段落和现有 citation keys，识别指定核心论文及用户已接受的正文。
- 本地原文足够时直接使用。PDF按页提取后核对双栏顺序、断词、页码与正文，必要时查看页面图像。
- 记录来源版本；期刊扩展版、会议正式版和预印本不能不加说明地混用页码或贡献描述。

## 查找支撑文献

优先使用出版方、会议官网、作者或机构提供的原始论文。搜索摘要、综述和第三方总结用于发现候选，
不能代替读取论文。只得到标题或元数据时，不据此生成具体方法描述。

背景引用达到数量要求之外，还必须符合主题、发表时间和出版质量要求：

- 同一论文的预印本和正式版按一篇计数。
- “顶会”应能说明所属领域和会议；不把熟悉的会议名称自动等同于用户要求的等级。
- SCI一区应记录采用 JCR 还是中科院分区，以及对应年份、学科；两种分区不互换。
- 未经核验不能声称一区。若一区标准不明，先核查可明确符合要求的会议；
  必须依赖期刊等级才能推进时再询问分区口径。
- 以当前日期计算新增文献的时间范围，区分预印本上线、在线发表与正式会议年份。
- 存在 GPU、workflow 等关键词不等于能支撑“serverless workflows”等更具体的论断。

可维护一个简短表格：论文、年份/会刊、质量依据、原文位置、支持的具体分句、核验状态。
这是核对工具，用户仅需要一句正文时无需输出整张表。

## BibTeX 与 LaTeX

- 先检查现有 .bib；沿用已存在的 key，不擅自重命名或重复插入同一论文。
- 新条目从出版方或可核对的一手来源取得题名、作者、年份、会刊和 DOI。
  保留正式题名，不把系统名擅自加到题名前。
- 页码、卷期或 DOI 不确定时省略相应可选字段并说明；不拼凑元数据。
- 保护必要的大写缩写和系统名，例如 `{GPU}`；正确转义作者姓名和特殊字符。
- 最终 citation keys 与所给 BibTeX 一致；只输出本次新增的条目，除非用户要求完整文献库。
- LaTeX 格式转换不改变已确认的措辞。若发现文字错误，单独提出更改建议。

## 无法获取来源时

- 本地材料、出版方或作者原文可相互补足；检索或工具不可用时说明具体缺失。
- 不将“未读到原文”写成“该文没有做”。可完成已核实部分，未完成项明确标记。
- 用户只提供片段时可据此改写，标明依据为所提供片段，不能声称读过整篇论文。
- 原文引用遵守当前环境的引用长度限制。只展示片段时，以页码、章节和段落定位所选完整句子。

## 文风核对

用准确动词连接机制与目的，例如 uses、combines、coordinates、allocates；选择由原文含义决定。
保留 end-to-end、tail latency、chance-constrained optimization 等有技术含义的表达。
删除不提供信息的褒义词；优化目标不能改写成未经原文支持的结果保证。
